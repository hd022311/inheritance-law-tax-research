# 俊德傳承法稅研究庫
Inheritance Law & Tax Research

整理繼承、特留分、保險與台美傳承相關的判決、法規、解釋令及官方資料

研究目的：協助事前傳承安排、辨識家庭分配風險、預留稅源，以及製作有依據的諮詢說明、講座與社群內容

本研究庫將「原始資料」「研究分析」「公開文稿」分開保存，讓每個結論都能回到來源核對

架構版本：v1.0
設計日期：2026-10-20

> 本 README 是第一版建置規格
> 下列目錄、模板與索引須另行建立
> 列入研究主題不代表已有法律結論，標示已核對也不代表可直接適用所有案件

## 1. 使用原則

1. 一份原始文件建立一張資料卡，多個主題共用同一張卡
2. 原文、摘要、研究者推論與待確認事項分開記錄
3. 每張資料卡保留官方來源、文件識別資料與查核日期
4. 判決結論必須連同個案事實、程序階段及適用限制閱讀
5. 法規與稅務資料必須記錄版本、適用年度及生效期間
6. 台灣與美國的法律、所得稅與遺贈稅判斷分開處理
7. 不以國籍、綠卡、戶籍或單一居留天數直接代替完整身分判斷
8. 不以「免列遺產」「免稅」「不必申報」等詞互相替代
9. 未取得全文、未確認日期或未查明效力的資料，明確標示待查
10. 公開內容以預留稅源、傳承效率及避免糾紛為主，不保證節稅結果

## 3. 資料卡與主題頁的差別

### 資料卡：回答「這份文件說了什麼」

一份判決、一個法規版本、一份函釋或一份官方指引，分別建立資料卡

同一判決同時涉及保險與特留分時，使用多個標籤，不複製成兩份資料卡

不同審級裁判各建一張卡，再用關聯欄位串接

### 主題頁：回答「這個問題應該怎麼研究」

主題頁整合多張資料卡，列出支持與不同見解、適用條件及待確認問題

例如：

- 身故保險金與特留分的關係
- 父母用子女名義開戶，財產歸屬如何判斷
- 要保人變更涉及哪些稅務與財產安排問題
- 台灣父母留保險金給美籍子女的文件準備
- 一名子女在台灣、一名在美國的房產分配安排

主題頁不得只引用其他主題頁，仍須能追溯原始資料卡

## 4. ID 與檔名格式

### 4.1 資料 ID

格式：

`地區-類型-六位流水號`

| 項目 | 代碼 |
|---|---|
| 台灣 | `TW` |
| 美國聯邦 | `US-FED` |
| 美國州別 | `US-州縮寫`，例如 `US-CA` |
| 判決 | `JUD` |
| 法規 | `LAW` |
| 解釋令、函釋 | `RUL` |
| 訴願等行政救濟決定 | `DEC` |
| 官方指引、FAQ | `GUI` |
| 官方表單及填寫說明 | `FRM` |
| 專業文章、研究報告等次級資料 | `SEC` |

例如：`TW-JUD-000001`、`US-FED-FRM-000001`

每組「地區＋類型」獨立編號，ID 建立後不再變更或重複使用

不同版本的法規、表單或指引使用不同 ID，並以 `version_group` 連結

### 4.2 檔名

格式：

`ID__文件日期__簡短主題.md`

例如，以下僅示範命名，不代表已有該文件：

`TW-JUD-000001__YYYY-MM-DD__身故保險金與特留分.md`

規則：

- 日期一律使用西元 `YYYY-MM-DD`
- 民國年保留在正式案號，日期欄另轉為西元
- 文件日期未知時，檔名使用 `undated`，日期欄填 `null`
- 不得用下載日期代替裁判、發布或修正日期
- 主題使用繁體中文，避免空白、斜線、冒號與問號
- 標題更動時保留 ID，並同步修正索引連結
- 不使用「最終版」「最新版2」等檔名

### 4.3 主題頁檔名

格式：

`TOPIC-六位流水號__簡短主題.md`

主題頁 ID 同樣永久保留

### 4.4 原始附件

格式：

`資料ID__original.pdf`
`資料ID__original.txt`

資料卡必須記錄附件路徑；OCR 文字另存 `資料ID__ocr.txt`，不得冒充原始全文

## 5. 每張資料卡的共同欄位

資料卡使用 UTF-8 Markdown，開頭以 YAML 保存欄位，後面撰寫研究內容

| 欄位 | 用途 |
|---|---|
| `schema_version` | 資料格式版本，第一版為 `1.0` |
| `id` | 永久資料 ID |
| `title` | 清楚描述文件或爭點 |
| `document_type` | `judgment/statute/ruling/decision/guidance/form/secondary` |
| `jurisdictions` | 法律適用地區，可複選 |
| `issuer` | 法院、機關或發布單位 |
| `official_identifier` | 正式案號、函令文號、法規名稱或表單編號 |
| `document_date` | 裁判、發布或版本日期 |
| `effective_from` | 生效日期，未知填 `null` |
| `effective_to` | 效力終止日期，未知或未確認填 `null` |
| `applicable_period` | 適用年度、課稅年度或事件期間 |
| `source_url` | 直接對應該文件的來源網址 |
| `source_level` | `official_primary/official_guidance/secondary` |
| `accessed_at` | 實際讀取來源的日期 |
| `review_status` | 整理與核對狀態 |
| `authority_status` | 來源效力狀態 |
| `last_verified_at` | 最近完成來源核對日期 |
| `tags` | 受控分類標籤 |
| `keywords` | 白話詞、金額、案號變體及中英文關鍵字 |
| `summary` | 80–150 字的檢索摘要 |
| `related_ids` | 相關資料 ID |
| `supersedes` | 本文件取代的舊版 ID |
| `version_group` | 同一法規或文件各版本的共同識別字 |
| `attachments` | 原始附件的相對路徑 |

所有欄位都保留，未知值使用 `null`，空清單使用 `[]`

`effective_to: null` 不代表已確認仍有效，須搭配 `authority_status` 判斷

### 狀態定義

`review_status`：

- `inbox`：只有線索，尚未取得或閱讀完整來源
- `draft`：已開始整理，內容尚待核對
- `verified`：已核對來源、重要段落與適用限制
- `needs_review`：有新資料、來源異動或內容衝突，須重查

`authority_status`：

- `unconfirmed`：尚未確認效力
- `current`：查核時確認適用的現行版本
- `historical`：歷史版本，仍可能適用過去事件
- `superseded`：已被後續文件取代
- `revoked`：已廢止或撤銷
- `not_applicable`：不適合以現行效力分類，例如一般研究文章或個別裁判

`verified` 只代表完成所列查核，不等於判決已確定，也不等於內容永久有效

## 6. 不同文件的追加欄位

| 文件類型 | 追加欄位 |
|---|---|
| 判決 | `court`、`case_number`、`case_type`、`procedural_stage`、`finality_status`、`case_group` |
| 法規 | `law_name`、`articles`、`amendment_date` |
| 解釋令、函釋、行政救濟決定 | `document_number`、`related_provisions`、`scope` |
| 官方指引、表單 | `revision`、`tax_year`、`related_provisions` |
| 次級研究資料 | `author`、`publisher`、`cited_primary_ids` |

判決的 `finality_status` 使用 `unconfirmed/final/not_final`

找不到上訴資料，不得直接填寫 `final`

裁判應另記錄：

- 事件發生時間與重要事實
- 當事人主張
- 法院認定的事實
- 法院處理的爭點與理由
- 主文及程序結果
- 引用法條與當時版本
- 上下審或後續裁判
- 哪些事實改變後，結論可能不同

不得把當事人主張當成法院見解，也不得把其他案件的引用文字當成本案結論

## 7. 台美傳承追加欄位

跨境主題頁與相關資料卡另設 `cross_border` 區塊

| 欄位 | 必須區分的內容 |
|---|---|
| `us_income_tax_status` | 美國所得稅身分與判斷前提 |
| `us_transfer_tax_status` | 美國遺產、贈與稅身分與判斷前提 |
| `taiwan_status` | 台灣相關稅籍、居住與身分條件 |
| `state_scope` | 是否涉及特定州，未知不得預設 |
| `asset_location` | 資產所在地及其認定問題 |
| `policy_roles` | 要保人、被保險人、受益人與實際繳費人 |
| `transfer_event` | 贈與、繼承、保險給付、解約或其他事件 |
| `payment_components` | 本金、身故給付、利息等款項性質 |
| `reporting_items` | 待研究的申報表單、義務人與觸發條件 |
| `tax_items` | 待研究的課稅項目，與申報義務分列 |
| `missing_facts` | 尚缺哪些事實才能判斷 |
| `supporting_ids` | 支持各項判斷的來源 ID |

執行規則：

- 所得稅身分與遺贈稅身分分別研究
- 美國聯邦與州法分別研究
- 是否課稅與是否申報分別研究
- 門檻金額、匯率規則、期限與表單版次必須註明年度及來源
- 每個判斷都列出適用條件，不只記錄表單名稱
- 不預設所有台灣保單在美國都有相同分類或效果
- 個案身分及保單資料缺漏時，保留待查，不補造事實

只有實際涉及的議題才加標籤，不為增加搜尋曝光而大量標註

資料卡本文固定使用以下標題：

### 一、文件與適用背景
記錄來源、事件或版本背景，以及理解文件所需的事實

### 二、核心問題
列出文件實際處理的問題，不擴張成所有類似情況

### 三、原文重點
摘錄必要文字，逐段標明條號、頁碼、段落或章節

### 四、來源明確支持的結論
每一項結論連到對應原文位置

### 五、研究者分析
說明推論過程，與來源原意清楚區分

### 六、適用條件與限制
哪些條件必須成立、哪些情況不能直接套用

### 七、事前安排的啟發
可提前盤點的資產、家庭分配、稅源、保單角色或文件問題

### 八、待確認事項
缺少的事實、效力、後續裁判或其他來源

### 九、關聯資料
列出相關 ID、相對連結，以及支持、補充或衝突的關係

### 十、查核紀錄
記錄查核日期、來源、完成項目與尚未完成項目

沒有完成查核的段落保留待查，不以流暢文字掩蓋資料不足

## 10. 主題頁模板

主題頁至少包含：

1. 主題 ID、標題與更新日期
2. 要回答的具體問題
3. 適用地區、年度與假設條件
4. 已核對的來源 ID
5. 各來源支持的結論與限制
6. 不同見解或衝突來源
7. 目前可以回答的部分
8. 還不能回答的部分與原因
9. 事前可盤點的安排
10. 對應的內容草稿路徑

比較表建議格式：

| 問題 | 支持來源 ID | 原文位置 | 適用條件 | 不同見解／限制 |
|---|---|---|---|---|

不得以「最新一份來源」自動消除其他來源的差異，應確認是否涉及不同事實、年度、法域或程序

## 11. 匯入規則

### 第一步：接收線索

接受官方網址、完整案號、文件全文、PDF 或截圖

只有案號或截圖時先存 `inbox/`，標示缺少哪些資料

檔名使用：

`收件日期__簡短主題.md`

此處收件日期只表示進入研究庫的日期，不是文件日期

### 第二步：取得並核對來源

優先使用：

- 台灣法院及司法院的正式裁判資料
- 全國法規資料庫與主管機關的法規資料
- 財政部及所屬機關的正式函令、決定與說明
- 美國官方法規、IRS 官方文件及相關州政府資料

專業文章可作為研究線索或不同分析來源，但不能冒充官方結論

新聞、社群貼文與 AI 回答不得直接作為法律結論依據

### 第三步：檢查重複與版本

- 判決：比對法院、完整案號、裁判日期與文件類型
- 法規：比對法規名稱及版本日期
- 函釋：比對發布機關、文號與日期
- 表單：比對表單編號、適用年度與修訂版次
- 不以網址作為唯一去重依據

同一文件的不同網址合併記錄

不同審級、不同裁判文件或不同版本各自建立資料卡

### 第四步：建立資料卡

分配 ID、補齊欄位並依模板整理

無法辨識的 OCR 文字標記為 `[辨識不清]`，不得猜測關鍵金額、日期或法條

官方網址無法直接定位文件時，補寫搜尋條件及文件識別資料，並標示來源限制

### 第五步：核對內容

至少確認：

- 文件識別、日期與來源一致
- 摘要沒有把主張寫成認定
- 引用文字與位置可核對
- 判決結果與程序階段正確
- 法規、門檻與表單適用年度明確
- 推論與原文分開
- 未解決事項已列出

### 第六步：同步索引

每次新增、更名、移動或更新資料卡，必須同步：

- `indexes/catalog.csv`
- 對應的主題索引與主題頁
- `indexes/open-questions.md`
- 必要時更新 `indexes/aliases.yml`

完成檢查後才標示 `verified`

第一版由整理者或 Codex 在同一次修改中維護索引；僅貼入 README 不會自動產生索引或開始抓取資料

## 12. 方便 ChatGPT 查詢的索引

### 12.1 總索引：catalog.csv

一張資料卡一列，包含所有狀態，方便看見哪些資料仍待查

欄位順序：

```csv
id,title,path,document_type,jurisdictions,issuer,official_identifier,document_date,applicable_period,review_status,authority_status,last_verified_at,tags,keywords,summary,source_url,related_ids
```

規則：

- `path` 是從研究庫根目錄起算的相對路徑
- 多值欄位以 `|` 分隔
- 日期採 `YYYY-MM-DD`
- 未知欄位留空，不填入猜測值
- 摘要維持單行，方便搜尋與匯入
- 含逗號、雙引號的文字依標準 CSV 規則處理
- 索引必須與資料卡欄位一致
- 資料卡是正文依據，索引只協助找到正文
- 已移除的檔案不得留有失效路徑

### 12.2 主題索引：topics.md

按下列四個主要入口整理：

- 繼承與遺產分配
- 特留分、歸扣與家庭爭議

- 台美身分、跨境移轉與申報

各入口連到主題頁；主題頁再連到資料卡

索引列出標題、適用地區、狀態與最後查核日期，避免只看到醒目結論

### 12.5 ChatGPT 檢索順序

1. 讀取 README，理解欄位與狀態
2. 搜尋總索引與同義詞，列出候選資料 ID
3. 依地區、年度、事件類型與狀態篩選
4. 開啟候選資料卡正文
5. 閱讀對應主題頁與關聯來源
6. 對時效性或效力有疑問的結論重新查核官方來源
7. 回答時列出 ID、原文位置、來源與限制

只有索引、搜尋摘要或檔名時，不得聲稱已閱讀正文

沒有找到資料時，回答「本研究庫尚無足夠資料」，不得推論法律不存在相關規定

ChatGPT 必須實際取得研究庫內容才能依此查詢；只有 GitHub 網址不代表已自動同步、完整讀取或完成全文搜尋

## 15. 對外內容轉用規則
